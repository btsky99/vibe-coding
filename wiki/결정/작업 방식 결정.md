### 🧠 feedback_clipboard_crlf

**navigator.clipboard.writeText에 LF만 넣으면 일부 입력창이 줄바꿈을 인식 못해 한 줄로 합쳐짐**

PyWebView/WebView2의 `navigator.clipboard.writeText("a\nb")`는 LF를 그대로 보존하지만, Windows의 일부 입력창(특히 Claude Code CLI 등 SingleLine-ish UI)은 LF만으로는 새 줄로 인식하지 않고 한 줄로 합쳐버린다.

**규칙:** 프론트에서 클립보드에 텍스트를 쓸 때는 항상 LF/CR을 CRLF로 정규화한다.
```ts
const text = source.replace(/\r\n|\r|\n/g, '\r\n');
navigator.clipboard.writeText(text);
```

**Why:** ToolsPanel 프롬프트 복사 시 줄바꿈이 사라져 한 줄로 붙여넣기 되는 사고 발생 (2026-05-10). 백엔드 JSON은 \n 정상 직렬화 — 원인은 클라이언트 클립보드 단계.

**How to apply:** Windows 대상 PyWebView/WebView2 앱에서 `navigator.clipboard.writeText` 사용하는 모든 곳에 적용. 다른 클립보드 호출(다운로드 텍스트 등)에도 동일 규칙 적용 권장.

출처: 세션 메모리 `feedback_clipboard_crlf.md` · type=feedback

### 🧠 feedback_no_hacks

**버그 수정 시 증상 가림/임시방편 금지. 항상 근본 원인을 찾아 구조적으로 수정**

사용자는 편법/임시방편을 싫어한다. 버그를 만나면 "빨리 덮는" 수정 대신 근본 원인을 찾아 구조적으로 고쳐야 한다.

**Why:** 2026-04-09 오피스 창 localStorage 저장 안 되는 문제 논의 중 명시 — "근본적 수정을 해야지 나는 편법은 싫어". 증상만 가리면 나중에 똑같은 문제가 다른 모습으로 재발한다는 걸 사용자가 분명히 인지하고 있음.

**How to apply:**
- 수정안이 2개 이상일 때 "빠른 우회"보다 "구조 개선"을 우선 제안
- 여러 창/프로세스가 같은 데이터를 다룬다면 → 분산 저장(localStorage)보다 중앙 저장(DB/API) 제시
- 하드코딩된 UI/레이아웃을 발견하면 동적으로 바꾸는 안을 포함
- "A안(30분, 임시) vs B안(2시간, 근본)" 제시 후 사용자가 고르게 하기보단, 먼저 B안을 기본 추천
- 기존 버그 수정 후 "이건 덮어놓은 거야" 같은 멘트 금지 — 해결했으면 명확히, 못 했으면 남은 구조 문제를 적시

출처: 세션 메모리 `feedback_no_hacks.md` · type=feedback

### 🧠 feedback_office_classic_separation

**오피스 모드 채팅과 클래식 모드 메시지는 완전히 분리되어야 함**

오피스 채팅 메시지는 `type: 'office_chat'`을 사용하고, 클래식 모드 메시지(info/handoff 등)와 절대 섞이면 안 됨.

**Why:** 사용자가 명시적으로 요청 (2026-04-10). "클래식 모드는 따로, 오피스 모드는 따로 관리"

**How to apply:**
- 오피스 채팅 send 시 `type: 'office_chat'` 사용
- OfficeChatPanel에는 `messages.filter(m => m.type === 'office_chat')` 전달
- 클래식 채팅 패널에는 office_chat 타입 메시지 제외

출처: 세션 메모리 `feedback_office_classic_separation.md` · type=feedback
