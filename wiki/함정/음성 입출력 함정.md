## 🔴 밟았던 것 (사고 장부)

> 재발 이력이 있는 사고 1건이 맨 위에 있다 — 한 번 더 밟기 전에 여기부터 읽을 것.

### 음성 설정이 '음성 엔진 준비 중'에서 안 넘어감

- **원인** — 낭독 경로가 사이드카 하나뿐(첫 기동 ~2분) + 준비 상태 재조회가 '목소리' 팝오버 안 3초 폴링뿐이라 팝오버를 닫으면 ready=true 를 영영 못 받아 표시가 고착
- **수정** — 브라우저 내장 합성기 우선 경로 신설(lib/browserVoice.ts) + 준비 폴링을 voiceBus.ensureSidecar 로 이관 + ready 를 '읽어 줄 수 있는가'로 재정의(sttReady 분리) — 48219b3
- 출처: `incident_ledger` · 재발 2회 · 최초 2026-08-15

### 음성 사이드카 /status 가 404 를 돌려주고 목소리/마이크가 동작 안 함

- **원인** — VOICE_PORT 9021 이 LAN 브리지와 충돌. 포트 지도의 '다음 빈 자리'를 잡았는데 LAN 브리지는 한 자리가 아니라 인스턴스마다 9020,9021,.. 로 번진다. status 요청이 LAN 브리지로 가 404
- **수정** — VOICE_PORT 9021 -> 9030 (voice_api.py + voice_server.py 양쪽). 포트 지도의 다음 자리는 안전하지 않다는 주석 추가
- 출처: `incident_ledger` · 최초 2026-08-15

### 마이크 모양이 화면에 아예 없다 (음성 기능 커밋 후)

- **원인** — 원인 2개. (1) 프론트 dist 를 빌드하지 않아 앱이 옛 번들을 서빙 — dist 에 '호출어' 문자열 0건. (2) VoiceBar 를 터미널 입력줄 안쪽에 뒀는데 그 입력줄은 isTerminalMode 일 때만 존재 — 에이전트 선택 카드 화면에서는 음성 UI 가 통째로 사라짐
- **수정** — npm run build 로 dist 갱신 + VoiceBar 를 슬롯 최하단(isTerminalMode 밖)으로 이동해 항상 렌더
- 출처: `incident_ledger` · 최초 2026-08-15

### 음성 설정이 '음성 엔진 준비 중…'에 영구 고착 + 마이크 입력 무동작 (백엔드는 ready:true 정상)

- **원인** — 원인 2개. (1) VoiceSettings 폴링 종료 조건이 v.voices.length인데 표시 조건은 v.ready — 서버 /status는 list_voices()를 엔진 로딩과 무관하게 즉시 주므로 첫 응답에서 목록이 차는 순간 폴링이 멈추고 뒤늦은 ready=true를 영영 못 받음. (2) 마이크 권한 배선이 create_window 직후 실행돼 Microsoft.Web.WebView2 import가 항상 실패(어셈블리는 webview.start()가 edgechromium을 import할 때 clr.AddReference로 로드됨). 그걸 고치니 이번엔 CoreWebView2 can only be accessed from the UI thread 예외
- **수정** — (1) 폴링 종료 조건을 v.ready로 통일 — 표시가 보는 값과 폴링이 멈추는 값을 일치시킴. (2) 배선을 events.loaded 이후로 미루고, CoreWebView2 읽기/이벤트 구독을 모두 inst.Invoke(Func[Type])로 UI 스레드에서 실행. 검증: '[voice] 마이크 권한 배선 완료' 최초 출력
- 출처: `incident_ledger` · 최초 2026-08-15
