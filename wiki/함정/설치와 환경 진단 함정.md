## 🔴 밟았던 것 (사고 장부)

### 설치 시 DeleteFile 실패 코드5: pgsql/bin/libcrypto-3-x64.dll 액세스 거부

- **원인** — InitializeSetup이 vibe-coding.exe만 taskkill, 자식 postgres.exe/node.exe가 고아로 살아남아 pgsql DLL 잠금. onedir은 DLL을 설치폴더에 직접 배치해 잠금 노출
- **수정** — InitializeSetup+UninstallRun에서 경로가 VibeCoding 설치폴더 밑인 프로세스만 스코프 종료(KillLockingProcesses). 개발체크아웃(vibe-coding 하이픈)/타 PG는 제외
- 출처: `incident_ledger` · 최초 2026-07-10

### dev 버전 auto 작동 안 함 (heartbeat 미시작)

- **원인** — 구버전 설치본 EXE(v3.7.269, PG keepalive 수정 前)가 절전발 죽은 PG 소켓에 걸려 _cycle DB 쿼리 recv()에서 무한 hang. loop_beat 23h 정지. 그 설치본이 싱글턴 락 포트 9019를 계속 점유 → dev server(v3.7.270)의 _acquire_singleton()이 None 받고 heartbeat 스레드 즉시 종료 → dev auto 시작 불가
- **수정** — hung 설치본 프로세스 종료(포트 9019 해제) 후 dev 서버 재기동. 근본: keepalive 수정은 v3.7.270에 이미 있으나 설치본이 269라 미반영. 구조적 구멍: 싱글턴이 stale-takeover 없어 죽은 락 주인을 아무도 인수 못함
- 출처: `incident_ledger` · 최초 2026-07-20

### 설치 중 오류: DeleteFile 실패; 코드 5 (액세스 거부) - {app}\_internal\msvcp140.dll

- **원인** — CloseApplicationsFilter=*vibe-coding*가 '닫을 앱' 필터가 아니라 '사용중 검사할 파일명' 필터라 _internal\*.dll이 Restart Manager 검사에서 제외됨 + KillLockingProcesses가 InitializeSetup 1회뿐이라 언인스톨/압축해제 사이 훅(VIBE_HIVE_HOOK)이 exe를 재스폰해 잠금 재발
- **수정** — 필터를 *.exe,*.dll,*.pyd,*.chm으로 복원 + 종료 폴링(최대 12초) + CurStepChanged(ssInstall)에서 파일 복사 직전 재정리 (커밋 94da950)
- 출처: `incident_ledger` · 최초 2026-07-28

### Discord 응답이 부팅 배너/스피너 잔상으로 나옴 + 데몬 상태판 전부 꺼짐

- **원인** — connector 응답 캡처가 대화형 TUI 화면을 정규식으로 긁는 구조 / daemon_status running 판정이 스레드명 단독이라 popen 후 return하는 데몬을 오탐
- **수정** — 헤드리스 claude -p --output-format stream-json 캡처(api/connector_relay.py)로 교체, 자식 프로세스 레지스트리로 running 판정 보강(90da217)
- 출처: `incident_ledger` · 최초 2026-08-04

### 설치본에서 Discord 토큰 저장 시 Failed to fetch

- **원인** — do_POST 404 폴백이 요청 본문을 안 읽고 닫아 Windows가 RST 전송 → 브라우저 fetch가 네트워크 오류로 실패. 실제 원인(구버전 백엔드에 /api/config/discord 라우트 없음)이 완전히 은폐됨
- **수정** — 폴백에서 본문 배수 후 route_not_found JSON + Content-Length 반환 (94fd2f8). 진단법: curl은 404로 보이고 브라우저만 실패하면 본문 미배수 RST를 의심
- 출처: `incident_ledger` · 최초 2026-08-05
