### 🧠 feedback_project_id_pattern

**pg_store.py DB 쓰기 함수의 project_id 패턴 분류(A/B/C)와 dev 모드 가드 의미**

pg_store.py 등 데이터 계층의 DB 쓰기 함수는 `project_id` 인자를 받고 진입부에서 `assert_project_id(project_id, '<함수명>')`을 호출해 빈 값 유입을 dev 모드에서만 경고한다.

**Why:** Phase 2-2에서 Layer 1 16개 테이블에 `project_id NOT NULL DEFAULT ''` 강제 + 332행 backfill 완료. 그러나 여전히 빈 문자열로 INSERT되는 경로가 있어 멀티 프로젝트 격리가 불완전했다. Phase 2-4는 데이터 계층 진입부 가드로 누수 경로를 dev 모드에서 가시화한다. NOT NULL은 마지막 수문장(prod 안전), 가드는 dev 알람(개발 시 발견).

**How to apply:**
- **패턴 A** (호출자 인자): `def f(..., project_id='')` — 호출자가 명시. pg_store 신규/기존 쓰기 함수 기본형.
- **패턴 B** (내부 자동해결): 함수 내부에서 `current_project_id()` 호출 — pg_store는 default_root/config_file 의존성 때문에 사용 안 함, 서버/API 모듈에서만.
- **패턴 C** (누락): 빈 값 들어갈 수 있음 → A 또는 B로 변환 대상.
- **N/A** (의도적 전역): `state_key`/`agent_id` PK로 본질적으로 전역인 함수(`save_state`, `record_heartbeat`, `_refresh_agent_stats`). 가드 추가하면 시끄러우니 그대로 둠.
- **가드 위치**: 함수 진입부 첫 줄 (조기 반환 다음). `dict.get('project_id')` 폴백이 있으면 폴백 직후.
- **시그니처 변경**: 신규 인자는 default `''`로 추가해 하위 호환 보존. 호출자 grep으로 영향 확인.
- **dev 활성화**: `VIBE_DEV_MODE=1` 환경변수. prod는 무동작.

**Phase 2-4 (2026-05-02) 적용 결과:**

### 🧠 project_api_econnreset

**클로드 코드 \"API Error ECONNRESET\" 반복 — 2026-08-02 원인 조사, 배제 목록과 유력 후보**

증상: `API Error: Unable to connect to API (ECONNRESET)` + `Retrying attempt N/10`.
"몇 시간 잘 되다가 또" 주기로 반복. 데스크톱·노트북 **양쪽 모두**에서 발생.

**Why:** ECONNRESET은 TCP RST(연결 강제 종료)라 쿼터 초과(429)와 완전히 다른 계층이다.
쿼터로 오해하면 엉뚱한 곳을 판다. 2026-08-02 조사에서 아래를 실측으로 배제했다 —
같은 증상 재발 시 이 목록부터 확인하고 중복 조사하지 말 것.

**배제 완료 (2026-08-02 실측):**
- **쿼터/429** — ECONNRESET은 쿼터 에러가 아님. 당시 5시간 윈도우 3%로 여유. (7일은 74%였으나 별개)
- **구 메시 VPN** — `ExitNodeStatus: None`. API 트래픽이 VPN을 타지 않음
- **로컬 포트 고갈** — TIME_WAIT 660/16384(4%)에서 평형(30초에 +8). 고갈 아님
- **옵시디언/zettel_sync 무한 루프** — 로컬 파일·DB 작업이라 API 경로와 무관
- **훅 이중 실행** — 별개 사고로 수정됨(e62a7e2 + 9c0011a). API 호출량은 줄지만 ECONNRESET 원인은 아님

**유력 후보 (미검증):** 한국 금융보안 프로그램이 로컬 프록시로 상주하며 SSL 트래픽 검사.
실측 확인된 점유: `INISAFECrossWebEXSvc`(127.0.0.1:4441), `delfino`/WIZVERA(16107·16117),
`veraport-x64`(16106·16116), `ASDSvc`/AhnLab(외부와 Established 유지).
양쪽 PC에 모두 깔려있어 "노트북에서도 난다"가 설명된다.

**How to apply:** 재발 시 검증 순서 — ① 트레이에서 안랩/이니세이프/베라포트 종료 후 테스트
② 공유기 재부팅(NAT 테이블 초기화) ③ 휴대폰 테더링으로 전환. ①에서 해결되면 확정.
평소엔 꺼둬도 되고 은행 접속 시 자동 재기동된다.

#### 확정 설계 (A안: 별도 브리지 프로세스)
- **왜 A안**: 기존 서버 전부 `127.0.0.1` 바인딩(로컬 전용) — 통째로 `0.0.0.0` 노출하면 모든 API가 LAN에 뚫림(위험). 별도 `lan_bridge.py`(`0.0.0.0:9020`)만 노출해 파일/채팅 라우트만 열고 기존 서버 보안 불변. `office_server.py`의 검증된 독립프로세스+포트자동탐색 패턴 복제. server.py 1500초과 문제도 안 건드림.
