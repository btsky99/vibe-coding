## `.ai_monitor/setup_doctor.py`

### _refresh_env_path `[WHY]`

CLI 감지 직전에 PATH를 레지스트리 기준으로 재병합한다(실패해도 진단은 계속).
[WHY 지연 import] setup_doctor는 `python .ai_monitor/setup_doctor.py`로 단독 실행되기도

다른 한쪽에서 ImportError로 진단 전체가 죽는다 — 진단기는 어떤 경우에도 살아야 한다.

출처: `.ai_monitor/setup_doctor.py:53`

### 모듈 상단 `[WHY]`

필수 훅 정의 — 각 이벤트에 필요한 명령어 목록
[WHY 인자 없음] 훅은 이벤트 페이로드를 stdin JSON으로 받는다(hook_bridge.main()의
`json.loads(sys.stdin.read())` → `data['prompt']`). 과거엔 `"$PROMPT"`를 argv로 넘겼지만
Claude Code는 명령 문자열에 셸 변수 치환을 하지 않아 리터럴 `$PROMPT`가 전달됐고,
받는 쪽은 argv를 아예 읽지 않아 무의미했다. 인자를 늘리려면 stdin 스키마를 쓸 것.

출처: `.ai_monitor/setup_doctor.py:159`

### _as_group `[불변식]`

flat 훅 정의를 Claude Code 정식 그룹 형식으로 감싼다.
[불변식] settings.json의 hooks.<event>는 반드시 {matcher, hooks:[...]} 그룹 배열이다.
flat {type, command}를 직접 넣으면 CLI 스키마 검증에서 hooks 키 누락으로 거부된다.

출처: `.ai_monitor/setup_doctor.py:176`

### _script_names `[WHY]`

command 문자열에서 실행되는 .py 스크립트 파일명만 뽑는다.
[WHY] 오염분과 정상 항목은 인자/인용 부호가 달라(`...hook_bridge.py` vs
`"...hook_bridge.py" "$PROMPT"`) 문자열 동등 비교로는 중복을 못 잡는다.
같은 스크립트가 두 번 등록되면 훅이 두 번 실행돼 pg_logs `[지시]`가 2줄씩 찍혔다.

출처: `.ai_monitor/setup_doctor.py:205`

### _normalize_event `[WHY]` `[불변식]`

[불변식] 정상 그룹은 원본 그대로 보존한다. 버리는 쪽은 항상 flat 잔재 — 사용자가

출처: `.ai_monitor/setup_doctor.py:215`

## `scripts/setup_voice.py`

### 모듈 상단 `[WHY]` `[제약]`

음성을 안 쓰는 사람도 onnxruntime·ctranslate2 200MB+ 를 받는다. 음성은
쓰겠다고 한 사람만 깔면 되는 기능이라 설치 경로를 분리했다.

3.13 에 없다(2026-08). 3.13 venv 로 만들면 설치가 컴파일로 떨어져 실패한다.
uv 는 --python 3.11 로 없는 버전을 알아서 받아 온다 — 그래서 uv 를 먼저 본다.
[제약] 이 스크립트는 앱 venv 에서 돈다. 만들어지는 것은 다른 venv 다 —
자기 자신에게 설치하지 않는다.
