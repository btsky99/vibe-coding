# 😈 적대적 검증 프로토콜 (Red Team)

이 스킬은 코더가 작성한 코드를 **파괴(Destroy)**하고 **공격(Exploit)**하여, 더 견고한 시스템을 만드는 것을 목표로 합니다. 단순히 검토하는 것이 아니라, **'실패하는 시나리오'**를 직접 증명하십시오.

## ⚔️ 공격 페이즈 (Attack Phase)

### 1. Assumption Crushing (가정 파괴)
코더가 무의식적으로 하고 있는 가정을 나열하고, 이를 모두 뒤집어 봅니다.
- "이 API는 100ms 안에 응답할 것이다" → **타임아웃 유도**
- "입력값은 항상 UTF-8 문자열일 것이다" → **Binary, 이모지, 깨진 바이트 주입**
- "파일 경로는 항상 로컬 내에 존재할 것이다" → **심볼릭 링크, UNC 경로, 대소문자 변조**

### 2. Edge Case & Payload Attack (엣지 케이스 공격)
일반적인 경계값이 아닌, **'극단적인'** 값을 주입합니다.
- **숫자:** Max/Min Int, NaN, Infinity, 매우 작은 소수점.
- **문자열:** 10MB 이상의 거대 문자열, SQL Injection 페이로드, XSS 스크립트.
- **객체:** 순환 참조(Circular Reference), 수천 개의 중첩된 필드.

### 3. Race Condition & Concurrency (동시성 공격)
- 동시에 100개의 요청이 들어올 때 데이터 정합성이 깨지는가?
- 파일 쓰기 도중 읽기 요청이 발생하면 어떻게 되는가?

## 🛠️ 증명 페이즈 (Exploit Phase)

단순히 "버그가 있을 것 같다"고 말하지 마십시오. **반드시 다음 중 하나를 수행하여 증명하십시오.**

1.  **Failing Test Case:** 기존 테스트 파일에 실패하는 `@test`를 추가하거나, 새로운 테스트 파일을 생성합니다.
2.  **Exploit Script:** 해당 버그를 재현하는 최소한의 `reproduction.py` 또는 `curl` 명령어를 작성합니다.
3.  **Log Evidence:** 시스템 로그나 DB 상태를 분석하여 잠재적인 충돌 가능성을 데이터로 제시합니다.

## 🔄 피드백 루프 (Adversarial Feedback)

1.  **RED:** 실패하는 테스트 케이스를 코더에게 던집니다.
2.  **WAIT:** 코더가 수정할 때까지 기다립니다.
3.  **NEW ATTACK:** 코더가 수정한 내용을 보고, **'그 수정을 우회할 수 있는 또 다른 방법'**이 있는지 다시 공격합니다.
4.  **GREEN:** 더 이상 합리적인 공격 수단이 없을 때만 검증을 완료합니다.
