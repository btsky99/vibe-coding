# 실행 그래프 (Agent Graph)

## 왜 이 문서가 생겼나

2026-08-11 하루에 고친 결함 3건이 **전부 같은 종류**였다.

| 결함 | 실체 |
|---|---|
| 중앙 대화 리스너 무음 | "60초마다 커넥션을 **재평가한다**"는 엣지가 **주석에만** 있고 코드엔 없었다 |
| 슬롯 멘션 `@1-2` 수신 소실 | 발신 엣지는 있는데 수신 조건이 어긋나 화면 폴링이 걸러냈다 |
| CI 버전 커밋 유실 | "push가 거부되면 어디로"가 정의되지 않아 `exit 0`이 실패를 삼켰다 |

셋 다 **코드는 돌고 있었고 로그도 조용했다.** 결과가 틀렸다는 것만 알 뿐 어느 연결이
끊겼는지 몰라 매번 추적에 시간이 들었다. 원인은 기능이 아니라 구조다 —
**엣지가 선언돼 있지 않고 코드 곳곳에 흩어져 있다.**

이 문서는 그 엣지를 선언한다. 특히 **실패하면 어디로 가는가**를.

> 용어와 원칙의 출처: 「그래프 엔지니어링 (Graph Engineering) 정리」(2026-08-11).
> ⚠️ **GraphRAG(지식그래프)와 다르다.** 그건 데이터 모델링(무엇을 기억하나),
> 이 문서는 실행 모델링(누가 다음에 뛰나)이다. 회상·제텔 쪽은 그 반대편이다.

## 용어

| 요소 | 이 프로젝트에서 |
|---|---|
| **노드** | 훅, 데몬 스레드, API 핸들러, 스킬, **사람의 확인 단계** |
| **엣지** | 앞 노드의 산출이 뒤 노드의 입력이 되는 길 |
| **스테이트** | PG 테이블(`hive_tasks`·`agent_messages`·`active_session_context`), 커서, config |
| **컨디션** | 재시도 상한, 승인 필요 여부, 임계치(컨텍스트 85% 등) |

## 원칙 — 이미 지키고 있는 것

**판단은 AI, 규칙은 코드, 중요·불가역은 사람.**

| 결정 | 맡는 곳 | 이 프로젝트의 실제 |
|---|---|---|
| 셀 수 있음 | **코드** | 컨텍스트 85% 임계, 재시도 상한, 1500줄 제한, 프롬프트 글자 상한 |
| 해석 필요 | **AI** | 설계 판단, 원인 추정, 코드 리뷰 |
| 중요·불가역 | **사람** | vibe-brainstorm 승인, 배포, 타 기기 변경, 보안 노출 |

새 기능을 붙일 때 이 표에서 **어느 칸인지 먼저 정한다.** AI가 필요 없는 곳에 AI를 쓰면
비용과 비결정성만 늘어난다.

## G1. 사용자 턴 (훅 체인)

```
[사용자 입력]
   ↓
UserPromptSubmit ─┬→ hive_hook.py    → 회상 주입(경험·지식·사고) + 워크플로 자동 감지
                  └→ hook_bridge.py  → 서버 기동 확인
   ↓
[LLM 판단]
   ↓
PreToolUse  → hive_hook.py → 민감 파일·sudo·외부 HTTP 차단  ──(차단)──→ [도구 실행 취소]
   ↓
[도구 실행]
   ↓
PostToolUse → hive_hook.py → 활동 기록(pg_logs)
   ↓
Stop ─┬→ hive_hook.py     → 세션 정리
      └→ claude_hook.py   → 종료 처리
```

| 항목 | 값 |
|---|---|
| **스테이트** | `pg_logs`, `hive_memory`, 회상 블록(프롬프트에 주입되는 텍스트) |
| **컨디션** | 유사도 임계(전역 0.55 / `agent_experience` 0.66) 미만은 주입하지 않음 |
| **🔴 실패 시** | 훅이 실패해도 **턴을 막지 않는다**. 회상은 편의이지 전제조건이 아니다 |

**차단은 PreToolUse 하나뿐이다.** 다른 훅에 차단 로직을 넣지 말 것 — 어디서 막혔는지
추적 불가능해진다.

## G2. (철거) 중앙 대화 — 노드 간

2026-08-14 아픽스 계층 전면 철거로 **이 엣지는 존재하지 않는다**(`346a33d`, 후속 정리).
`central_api` / `central_listener` / `agent_messages` 는 이 리포에 없다. 노드 간 대화가
다시 필요해지면 여기에 먼저 '실패하면 어디로'를 적고 배선한다 — 그게 이 문서의 존재 이유다.

> 남은 교훈 한 줄: **화면에 뜨는 것과 CLI 에 꽂히는 것은 다른 엣지다.**
> 수신 경로를 만들 때 '표시'와 '주입'을 한 엣지로 뭉치면 진단이 불가능해진다.

## G3. 컨텍스트 리사이클 — 잘 된 예

이미 명시적 상태 머신이다. **새 배선은 이 형태를 본뜬다.**

```
GUARD ──(불통과)──→ [아무것도 하지 않음]
  │ 통과
SEAL   ──(실패)──→ 🔴 [중단] terminate 호출 금지
  │
DRAIN  (최대 20초)
  │
  ├─ user_active 재확인 ──(사람이 타이핑 중)──→ [중단]
  │
SWAP ──(실패)──→ 프롬프트를 파일로 보존(save_fallback)
  │
REANCHOR (≤1500자, 중간 절단)
```

| 항목 | 값 |
|---|---|
| **스테이트** | `active_session_context`(intent/next_step 각 200자) |
| **컨디션** | 컨텍스트 85% 초과 · 플래핑 가드 60초 · `user_active` |
| **🔴 실패 시** | 각 단계가 **어디로 가는지 코드에 적혀 있다.** 이것이 G2·G4와의 차이다 |

**왜 모범인가**: GUARD 판정이 순수 함수이고 실행은 주입된 deps 경유라 각 노드를
독립적으로 검증할 수 있다. 불변식이 주석이 아니라 **테스트로** 고정돼 있다.

## G4. 배포

```
[코드 커밋] → push(main)
   ↓
paths-ignore 판정 ──(전부 md/docs/scripts-remote)──→ [빌드 건너뜀]
   ↓ 코드 포함
Build & Release (20분)
   ↓
버전 확정: 태그 중복이면 patch++
   ↓
_version.py 커밋 → push ──(거부)──→ 🔴 rebase 후 3회 재시도 ──(그래도 실패)──→ ::warning:: 노출
   ↓
EXE/DMG 빌드 → 릴리즈 발행 → [사용자 자동 업데이트]
```

| 항목 | 값 |
|---|---|
| **스테이트** | `_version.py`(진실의 원천), git 태그, 릴리즈 자산 |
| **컨디션** | 태그 존재 여부, `paths-ignore`, `GITHUB_REF == main` |
| **🔴 실패 시** | push 거부 → 재시도 → 경고. **삼키지 않는다**(2026-08-11 이전에는 삼켰다) |

🔴 **빌드 중에는 추가 푸시를 하지 않는다.** 사람의 커밋이 CI의 버전 커밋을 밀어내
저장소와 배포본 버전이 갈라진다(v3.7.332 vs 333 사고).

## 규율 — 새 배선을 놓을 때

1. **엣지를 먼저 쓴다.** 코드보다 이 문서가 먼저다. "실패하면 어디로"가 안 적히면
   그 배선은 아직 설계되지 않은 것이다.
2. **주석에 적은 방어는 방어가 아니다.** 리스너 사고가 그것이었다 — 주석은
   "재평가한다"고 선언했지만 코드는 하지 않았다. 방어는 **테스트로** 고정한다.
3. **감지에서 멈추지 않는다.** 감지 → 재시도(상한) → 초과 시 **명시적 중단**까지가
   한 세트다. 로그만 찍고 성공 처리하는 것은 엣지가 없는 것과 같다.
4. **사람 게이트를 노드로 센다.** 승인 단계는 흐름의 일부이지 예외가 아니다.
5. **실패와 '정상적인 빈 결과'를 같은 값으로 뭉개지 않는다.** 두 엣지가 하나로 합쳐지면
   추적이 원리적으로 불가능해진다. 폴더 다이얼로그가 그랬다 — 다이얼로그를 못 띄운
   실패도, 사용자가 취소한 것도 똑같이 빈 문자열이었고, 프론트는 둘 다 조용히 넘겼다.
   증상은 "눌러도 아무 일이 없다" 하나뿐이라 어느 쪽인지 알 방법이 없었다
   (2026-08-11, 실제 원인은 셋째였다 — **창은 떴고 앱 뒤에 깔렸다**).

## 언제 그래프로 만들지 않는가

문서가 경고하는 오버엔지니어링 경계를 그대로 따른다.

- 한두 번의 도구 호출로 끝나는 작업에 노드를 나누지 않는다
- 노드를 늘리면 디버깅 지점이 늘고 **에이전트 수만큼 토큰이 녹는다**
- "모든 것을 그래프로"는 답이 아니다 — 이 프로젝트는 이미 [8·9차 정리]에서
  유령 UI와 관제 계층을 걷어낸 전례가 있다. 구조는 늘리는 것보다 줄이는 쪽이 어렵다

**그래프가 값을 내는 순간**: 여러 단계 + 조건 분기 + 실패 시 되돌아갈 지점 + 사람 개입.
G2·G4가 정확히 그랬고, 그래서 사고가 났다.
