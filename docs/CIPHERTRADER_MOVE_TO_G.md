## 🔴 함정 (다시 헤매지 말 것)

### 1. 옮길 폴더 안에서 PostgreSQL이 켜진 채 돌고 있다

```
"C:/CipherTraderPG/bin/postgres.exe" -D "D:/CipherTrader/.cache/ctpg_data"   pid 26604, 포트 5435
```
`postmaster.pid` 존재 확인함. **켠 채로 복사하면 복사본은 깨진 DB가 된다.**
크립토 창 셋(apix1-1·2-1·2-2)을 멈춰도 이 PG는 별도로 정상 종료해야 한다.

> 기존 메모리의 "PG 5435는 `C:\CipherTraderPG`로만 기동" 은 **바이너리 경로**를 말한 것이고,
> **데이터 경로는 D: 안**이다. 둘을 혼동하면 "DB는 D: 밖이니 그냥 복사해도 된다"고 오판한다.

### 2. G: 에 불완전한 옛 복사본이 이미 있다

`G:\CipherTrader_cache\rl_v31` = **38.19GB / 78파일**
원본 `D:\CipherTrader\.cache\rl_v31` = **70.47GB / 111파일**
→ 덜 옮겨진 조각이다. 그대로 두면 이전 후 대조가 어긋난다.
→ 정리하면 G: 여유가 38GB 늘어 잔여 7.4GB → 45GB 로 풀린다.

### 3. G: 에 `pagefile.sys` 가 있다

윈도우 가상메모리가 G: 에 얹혀 있다. 잔여 7.4GB로 몰면 pagefile 확장 시 드라이브가 찬다.
**"들어간다"와 "써도 된다"는 다르다.**

1. PG 정상 종료 확인 (`postmaster.pid` 소멸 확인)
2. `robocopy` **복사**(`/MOVE` 금지) — 6덩이로 분할, 창 없이(`infra.proc`, CREATE_NO_WINDOW)
3. 덩이마다 파일 개수 + 총 바이트 대조 → 로그 보존
4. `D:\CipherTrader` 문자열 전수 검색 → 박힌 경로 수정, 수정 목록 문서화
5. G: 에서 실제 기동 확인 (PG 5435 + 학습 1회)
6. **원본 정리는 결재 대기** — 자의로 지우지 않는다
