# 원격제어 (RustDesk 셀프호스트) — 운영 가이드

---

## 요약

| 항목 | 값 |
|------|-----|
| 소프트웨어 | RustDesk 1.4.9 (오픈소스, AGPL) + rustdesk-server 1.1.16 |
| 비용 | 0원 (계정·구독·기기 수 제한 없음) |
| ID/중계 서버 | **아픽스 서버**(서울 VPS)의 hbbs/hbbr — 제3자 서버 미사용 |
| 전송 경로 | P2P 홀펀칭(가능하면) / 실패 시 아픽스 서버 중계 |

**핵심 설계 판단**: ID 서버를 내 것으로 두는 이유는 *제3자 경유를 만들지 않기 위해서*다.
아픽스 서버는 공인 IP가 있으므로 NAT 뒤의 두 기기를 서로 만나게 해줄 수 있고,
홀펀칭이 실패해도 자기가 중계한다.

---

## 🔴 무엇이 나빠졌나 — 정직하게

예전 구조는 메시 VPN 위에 얹혀 있었고, 그래서 **공인망에 열린 포트가 0개**였다.
그 방식을 폐기하면서 이 성질은 사라졌다.

| | 예전 | 지금 |
|---|---|---|
| 접속 경로 | 사설망 안에서만 | 임의의 공인 IP에서 홀펀칭 |
| 인바운드 방화벽 | 사설 대역으로 축소 | **모든 주소 허용이 필요** |
| 유일한 방어선 | 네트워크 경계 + 비밀번호 | **비밀번호 16자 + hbbs 공개키 대조** |

인바운드를 좁힐 수 없는 이유는 상대의 공인 IP를 미리 알 수 없기 때문이다. 좁히면
P2P 직결이 막혀 매번 중계로 떨어지거나 아예 실패한다.

**따라서 비밀번호가 곧 접근 권한이다.** 메신저로 보내지 말고, 유출이 의심되면 즉시
재설정한다. 무인 접속이 켜져 있다 = 화면 앞에 아무도 없어도 조작된다.

## 2계층 구조

```
계층 1  아픽스 서버 hbbs 경유 (기본)
        9자리 ID로 접속. ID 등록·홀펀칭·중계를 내 서버가 맡는다.
        커버: 폰/탭 → PC / PC ↔ PC / 밖 → 집 PC / 부모님·지인 PC

계층 2  RustDesk 공용 서버 (폴백)
        내 서버를 쓰기 어려운 상대용. 제3자를 경유하므로 기본이 아니다.
```

> 예전의 "사설망 직결" 계층은 없다. 그 계층이 담당하던 *노출 0* 성질은
> 위 표대로 사라졌고, 대신 서버가 어디서든 도달 가능하다는 이점을 얻었다.

## 계층 1 — 내 기기 세팅

### Windows PC

```powershell
# 관리자 PowerShell
cd <저장소>\scripts\remote
.\Install-RustDeskClient.ps1 -IdServer 158.247.205.192 -Key '<hbbs 공개키>'
```

`-IdServer`를 빼면 RustDesk 공용 서버로 나간다(제3자 경유). 실사용에서는 항상 준다.
`-Key` 없이 `-IdServer`만 주면 클라이언트가 서버를 신뢰하지 못해 **조용히 실패**하므로
스크립트가 진입부에서 막는다.

끝나면 화면에 **RustDesk ID / 고정 비밀번호**가 출력된다.
비밀번호는 `%LOCALAPPDATA%\vibe-remote\rustdesk-password.txt` 에도 저장된다
(**저장소 바깥** — git에 절대 들어가지 않는다).

### 안드로이드 탭 / 폰

1. RustDesk 앱 설치 (Play 스토어 또는 GitHub APK)
2. 설정 > 네트워크 > ID/중계 서버
   - ID 서버 `158.247.205.192`
   - Key `<hbbs 공개키>`
3. ID 칸에 상대 PC의 9자리 ID 입력

### macOS

RustDesk `.dmg`를 받아 설치하고 설정 > 네트워크에 동일한 ID 서버/Key를 넣는다.
스크립트는 Windows 전용이라 맥은 GUI 설정으로 처리한다.

## 계층 1 확장 — 부모님 / 지인

> **일회용 대신 고정 ID로 간다.** 매번 "화면의 9자리 숫자를 불러주세요"를 요구하는 방식은
> 정작 도움이 필요한 상대에게는 쓸 수 없다. 한 번 세팅하면 이후로는 **상대가 아무것도
> 하지 않아도** 같은 ID·같은 비밀번호로 붙는다.
>
> 전용 스크립트: **`scripts/remote/Install-RustDeskForFamily.ps1`** (그 PC에서 관리자 권한 1회)

```powershell
# 기본 — 내 아픽스 서버 경유
.\Install-RustDeskForFamily.ps1 -IdServer 158.247.205.192 -Key '<hbbs 공개키>'

# 서버를 안 쓸 때 — RustDesk 공용 서버 경유
.\Install-RustDeskForFamily.ps1 -Mode public
```

끝나면 접속 정보가 화면과 그 PC 바탕화면(`원격접속-정보.txt`)에 남는다.
공용 PC라면 `-Password`로 직접 지정하고 그 파일을 지우는 편이 낫다.

`-Mode public`으로 세팅한 상대에게 붙을 때는 **내 쪽 ID 서버를 잠시 기본값(공백)으로**
되돌려야 한다 — 내 서버를 보고 있으면 공용 서버에 등록된 ID를 찾지 못한다.

### 🔴 절전 — 실패 원인 1위

원격제어가 안 되는 사고의 대부분은 소프트웨어가 아니라 **그 PC가 자고 있어서**다.
Windows 기본값은 유휴 30분 뒤 절전이고, 절전에 들어가면 네트워크에서 사라진다.
**인터넷 너머에서는 깨울 방법이 없다** — Wake-on-LAN은 같은 랜에서만 동작한다.

스크립트가 전원 연결 시 절전/최대절전을 해제하고, 노트북은 뚜껑을 닫아도 안 자게 만든다.
화면 꺼짐은 그대로 둔다(접속에 영향 없음). 배터리 구동 중 절전까지 끄려면
`-DisableSleepOnBattery`를 주되, 노트북이면 방전에 주의한다.

### IP가 바뀌면?

**내 기기 IP는 상관없다.** 접속은 9자리 ID로 하고, ID는 기기에 고정된다.
집·카페·테더링 어디로 옮겨도 동일하다.

바뀌면 곤란한 것은 **아픽스 서버 주소**뿐이다. 그건 VPS 고정 IP라 바뀌지 않는다.

## 보안 경계

- **인바운드 노출**: RustDesk 규칙은 모든 주소 허용이다(홀펀칭에 필요 — 위 "무엇이 나빠졌나").
  그 외 목적 없는 인바운드 규칙은 `Remove-InboundExposure`로 지운다.
- 인증은 **고정 비밀번호 16자** + hbbs **공개키 대조** 2중.
- hbbs 개인키는 서버 관리자만 읽을 수 있어야 한다. 유출되면 제3자가 이 ID 서버를
  사칭할 수 있으므로 백업 시에도 저장소·클라우드에 올리지 말 것.
- 무인 접속 = **비밀번호를 아는 사람은 화면 앞에 아무도 없어도 조작할 수 있다.**

### 방화벽 규칙의 함정

Windows 방화벽에서 허용 규칙은 **OR로 합쳐진다.** 설치 프로그램이 만든 "모든 주소 허용"
규칙이 하나라도 남아 있으면, 좁은 규칙을 아무리 **추가**해도 노출은 그대로다.
좁히려면 기존 규칙을 `Set-NetFirewallRule`로 **수정**하거나 아예 지워야 한다.
(`New-AllowedInboundRule`은 대역을 명시적으로 받는다 — 기본값 Any 로 실수로 여는 것을 막는다.)

## 포트 지도

| 포트 | 프로토콜 | 주인 | 용도 |
|------|----------|------|------|
| 21115 | TCP | hbbs | NAT 유형 판정 |
| 21116 | TCP+UDP | hbbs | ID 등록 · 홀펀칭 |
| 21117 | TCP | hbbr | 중계 |
| 21118 | TCP | hbbs | 웹소켓 |
| 21119 | TCP | hbbr | 웹소켓 중계 |
| 21128 | TCP | RustDesk 클라이언트 | 직접 IP 접속 (한 PC가 서버를 겸할 때 비켜난 값) |

> 21118이 기본값이 아닌 이유는 아래 함정 ① 참조.

---

## 실측으로 확인된 함정 (재발 방지)

### ① 서버와 클라이언트가 같은 PC면 21118이 충돌한다

hbbs는 21118을 웹소켓으로 고정 사용하는데 RustDesk 클라이언트의 직접 IP 접속 기본 포트도
21118이다. 나중에 뜨는 쪽이 `os error 10013`으로 **즉사**한다. hbbs의 포트는 기준 포트에서
파생돼 개별 변경이 불가하므로 **클라이언트가 21128로 비켜준다**. 스크립트가 자동 처리한다.

### ② 설정이 두 군데에 있다 — 한쪽만 고치면 무증상 실패

- 사용자 프로필: `%APPDATA%\RustDesk\config\` — **설정 화면**이 읽는다
- 서비스 프로필: `C:\Windows\ServiceProfiles\LocalService\AppData\Roaming\RustDesk\config\` —
  **실제로 원격 접속을 받아들이는 쪽**이 읽는다

사용자 프로필만 고치면 화면상으로는 반영돼 보이는데 실제 접속은 공용 서버로 나간다.
서비스 계정은 LocalSystem이 아니라 **LocalService**다 (`systemprofile` 경로는 존재하지 않는다).

또한 **서비스를 멈추고 써야 한다.** 살아 있는 서비스는 종료 시점에 자기 메모리 상태를 파일로
되쓰기 때문에, 돌아가는 중에 고치면 다음 재시작에서 조용히 덮인다.

### ③ 이 PC는 자기 자신의 비-루프백 주소로 못 붙는다

자기 주소:21116 으로 SYN을 보내면 RST도 방화벽 드롭 로그도 없이 그냥 타임아웃된다.
방화벽을 전면 허용해도, 평범한 `TcpListener`를 띄워 시험해도 동일 — 즉 **방화벽 규칙 문제가
아니라 "자기 자신의 비-루프백 주소로 들어오는 연결"이 이 호스트 환경에서 막혀 있다.**
(RustDesk 본체만 자체 프로그램 규칙 덕에 예외적으로 통과한다.)

→ hbbs를 겸하는 PC는 **자기 ID 서버 주소로 `127.0.0.1`을 쓴다.** 중계 주소(`relay-server`)는
원격 피어가 사용해야 하므로 원래 주소를 유지한다. 스크립트가 자동 판별한다.

> 이 증상의 근본 원인(보안 프로그램의 WFP 필터 등)은 규명하지 않았다.
> 원격제어 동작에는 영향이 없어 추적을 중단했다 — 다른 서비스에서 같은 증상이 보이면
> 여기를 먼저 의심할 것.

## 상태 확인 / 문제 해결

```powershell
# 클라이언트가 ID 서버에 붙었는지 (key_confirmed = true 면 등록 성공)
Select-String 'C:\Windows\ServiceProfiles\LocalService\AppData\Roaming\RustDesk\config\RustDesk.toml' -Pattern key_confirmed

# 실제 접속 로그
Get-Content 'C:\Windows\ServiceProfiles\LocalService\AppData\Roaming\RustDesk\log\server\RustDesk_rCURRENT.log' -Tail 30

# 내 RustDesk ID
& 'C:\Program Files\RustDesk\rustdesk.exe' --get-id
```

```bash
# 아픽스 서버 쪽 (ssh apix)
systemctl status hbbs hbbr
journalctl -u hbbs -n 30
```

`http://.../21114/api/sysinfo failed` 경고는 **무시해도 된다** — 21114는 유료판 API 서버
포트라 오픈소스 hbbs에는 존재하지 않는다.

`Install-RustDeskServer.ps1`은 hbbs를 **윈도우 PC에** 올리는 스크립트다. 집 PC는 공인 IP가
없어 밖에서 못 붙으므로 보통은 쓰지 않는다 — 아픽스 서버의 hbbs를 쓴다.

## 아직 검증되지 않은 것

- **원격 피어 왕복**: hbbs 기동·리슨·로컬 등록까지는 확인됐으나, *다른 기기에서* ID로
  접속하는 왕복은 여전히 검증하지 못했다. → 탭이나 다른 PC로 **한 번은 실제로 붙여봐야 한다.**
- **부모님/지인 경로**: 절차만 정리했고 실제 수행은 하지 않았다.
- **아픽스 서버 hbbs 경유 구성**: 스크립트는 이 구조로 고쳤으나 실제 접속 시험은 미실시.
