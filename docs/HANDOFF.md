## 1. 이 프로젝트가 무엇인가

AI 에이전트(클로드·코덱스 등) 여러 대를 한 창에서 띄우고, 그들이 한 일을 기록·공유하게
만드는 **윈도우 데스크톱 앱**이다. 화면은 React, 속은 파이썬 서버, 기록은 PostgreSQL,
터미널은 Node PTY 로 돈다. 겉보기엔 대시보드지만 **궁극 목표는 기능 확장이 아니다** —
세션이 끊겨도 다음 세션이 이어받고(연속성), 한 번 고친 에러를 두 번 고치지 않는 것
(재발 방지). 즉 **삽질 빈도를 줄이는 것**이 이 프로젝트의 존재 이유다.

방향은 **라이트하게**다(2026-08-14 사장 결정). 쓰지 않는 계층은 남기지 않는다 —
그래서 디스코드(`c6f3cda`)·아픽스 연동(`346a33d`)·관제 보드(`203c9f4`)를 전부 걷어냈다.

## 6. 조심할 것 (이 프로젝트만의 함정)

1. 🔴🔴 **main 에 push 하면 그것이 배포다.** `.github/workflows/build-release.yml` 이
   main push 마다 풀빌드+릴리즈를 돌린다. `.py` 하나만 섞여도 돈다.
   굽지 않고 푸시만 하려면 **머지/헤드 커밋 제목에 `[skip ci]`**.
   🔴 그래도 **설치본엔 닿는다** — soft_updater 는 커밋 SHA 만 본다. 막히는 건 새 EXE 굽기뿐.
2. 🔴 **사람이 안 시킨 실행은 콘솔 창을 띄우지 않는다**(절대규칙 10). `CREATE_NO_WINDOW`
   는 자식에게 **상속되지 않는다** — 말단 호출마다 `infra.proc` 를 거쳐야 한다.
   같은 결함으로 2번 밟았다(`d423a7d`, 2026-08-14).
3. 🔴 **PG(5433)는 앱이 띄운다.** 앱이 꺼진 밤에는 회상·사고장부·체크포인트·훅로깅
   **4장치가 전부 0**이다. "왜 기록이 없지"의 답이 대개 이것이다.
4. 🔴 **포트의 '다음 빈 자리'를 잡지 마라.** LAN 브리지가 9020, 9021, … 로 번진다.
   음성 사이드카가 9021 을 잡았다 조용히 죽어 9030 으로 옮겼다.
5. 🔴 **개발에서 되는 것과 설치본에서 되는 것은 다르다.** config 분리 + DB 공유 때문에
   `project_id` 슬러그가 어긋나 패널이 통째로 비는 사고가 있었다.
   배포 전 `/vibe-verify-installed` 로 실측한다.
6. 🔴 **브라우저가 아니라 PyWebView 네이티브다.** "브라우저 hard reload" 같은 지시는
   성립하지 않는다 — **앱 재시작** 또는 WebView F5.
7. 🔴 **사용자는 개발 비전문가다.** 결론을 먼저, 근거를 나중에. 선택지는 "A안/B안"이
   아니라 상황으로 제시한다(절대규칙 1).
8. 🔴 **글 쓸 때 백슬래시를 Bash 힘드(heredoc)로 넣지 마라.** 2026-08-19 실측 —
   `\vibe-coding.exe` 가 **세로탭으로 먹혀** `VibeCodingibe-coding.exe` 로 저장됐다.
   따옴표 친 `<< 'EOF'` 인데도 그랬다. 화면에는 그럴듯해 보여서 **안 잡힌다.**
   → 윈도우 경로가 든 글은 **Write/Edit 도구**나 **PowerShell** 로 쓴다.
   쓴 뒤 제어문자 0건을 확인한다: `[regex]::Matches($s,"[\x00-\x08\x0B\x0C\x0E-\x1F]").Count`
9. 🔴 **`apix-wiki`(서버 위키)는 `.cmd` 를 그냥 부르면 깨진다** — 래퍼 주석이 한글이라
   cp949 콘솔에서 토막 난다. 파이썬을 직접 부른다:
   `python "C:\Users\com\AppData\Local\Programs\apix-runner\apix_wiki.py" search "..."`
   (`$env:PYTHONIOENCODING="utf-8"` 를 먼저 건다.)
   🔴 **0장과 「못 닿았다」는 다른 것이다.** 종료코드 0 = 서버가 답함(0장 포함) · 3 = 못 닿음.
