# Miix 520 Vibe Coding 중앙 서버 전환 계획

## 1. 목표

Lenovo Miix 520-12IKB(메모리 8GB)를 24시간 동작하는 Vibe Coding 중앙 서버로 사용한다.

Miix 520에서 상시 실행할 항목:

- PostgreSQL 18 및 ITCP `pg_messages`
- Vibe Coding API 서버
- Telegram 봇(APIS 1·2·3)
- 필요한 자동 시작·상태 점검·복구 작업

개발용 Codex, Claude Code, Antigravity는 설치할 수 있지만 동시에 상시 실행하지 않는다. 실제 대규모 개발은 주력 PC에서 수행하고 Miix 520은 메시지 버스와 서비스 운영에 집중한다.

## 2. C드라이브 여유 공간 기준

| 상태 | 설치 전 여유 공간 | 판단 |
|---|---:|---|
| 설치 금지 | 20GB 미만 | Windows 업데이트와 DB 증가 공간이 부족함 |
| 최소 가능 | 25GB 이상 | 시험 운영은 가능하지만 자주 정리해야 함 |
| 권장 | 40GB 이상 | Vibe Coding과 PostgreSQL 운영에 적합함 |
| 장기 운영 권장 | 50GB 이상 | 24시간 운영, 로그, 업데이트에 비교적 안전함 |

권장 배분:

- Windows 업데이트·임시파일 여유: 15~20GB
- PostgreSQL 설치와 데이터 예약: 5~10GB
- Git 저장소·Python·Node 의존성: 5~10GB
- Codex·Claude Code 및 캐시: 3~8GB
- 장애 로그·백업·추가 여유: 5~10GB

따라서 설치를 시작하기 전에 **C드라이브 여유 공간을 최소 40GB, 가능하면 50GB 이상** 확보한다.

## 3. 공간 정리 원칙

삭제 전 사용자 자료를 외장 저장장치나 Google Drive에 백업한다.

우선 정리 대상:

1. Windows 설정의 임시 파일과 이전 업데이트 파일
2. 다운로드 폴더의 대용량 설치 파일
3. 사용하지 않는 앱과 게임
4. 브라우저·개발도구 캐시
5. 오래된 Windows 복원 지점

금지 사항:

- `Windows`, `Program Files`, `ProgramData` 폴더를 직접 삭제하지 않는다.
- PostgreSQL 데이터 폴더를 파일 탐색기에서 임의로 정리하지 않는다.
- 저장 공간 확보만을 위해 가상 메모리를 완전히 끄지 않는다.

외장 SSD나 빠른 USB 저장장치가 있다면 Git 저장소와 백업은 외장 장치로 옮길 수 있다. PostgreSQL의 실제 데이터는 연결 안정성을 위해 내부 SSD에 두는 것을 우선한다.

## 4. 하드웨어 준비

- Miix 520 전원 어댑터 상시 연결
- 듀얼 팬 태블릿 거치대 설치
- 별도 USB 충전기로 쿨링팬 전원 공급
- Wi-Fi보다 가능하면 USB 유선 LAN 어댑터 사용
- 통풍구를 막지 않고 후면 팬과 통풍 위치를 맞춤

24시간 시험 중 긁힘·달그락거림 같은 내부 팬 소리가 계속되면 외부 팬과 별개로 내부 팬 청소 또는 교체를 검토한다.

## 5. Windows 운영 설정

1. Windows 업데이트를 완료한다.
2. 전원 연결 시 절전과 최대 절전 모드를 해제한다.
3. 화면만 일정 시간 후 꺼지도록 설정한다.
4. 전원 복구 후 자동 시작이 필요한 서비스와 작업 스케줄러를 구성한다.
5. 야간 자동 재부팅은 초기 안정화가 끝난 뒤 주 1회 수준으로 검토한다.
6. 원격 관리를 위해 RustDesk 또는 Windows 원격 접속 수단을 하나만 선택한다.

## 6. 설치 순서

### 1단계: 기본 도구

- Git
- Python 프로젝트가 요구하는 버전
- Node.js 프로젝트가 요구하는 LTS 버전
- PostgreSQL 18(프로젝트 기준 포트 5433)
- Codex 및 Claude Code

설치 후 각 명령의 버전을 기록한다.

### 2단계: 저장소 이전

- Miix 520에 전용 작업 폴더를 만든다.
- Git 원격 저장소에서 `vibe-coding`을 복제한다.
- 비밀키와 Telegram 토큰은 Git에 넣지 않고 별도 환경설정으로 이전한다.
- 현재 PC의 변경되지 않은 설정만 복사하고 장치별 절대경로는 Miix 환경에 맞게 다시 지정한다.

### 3단계: PostgreSQL 이전

- PostgreSQL 18을 포트 5433으로 구성한다.
- 필요한 데이터베이스와 역할을 만든다.
- 기존 DB를 논리 백업한 뒤 Miix 520으로 복원한다.
- `pg_messages`, `pg_logs`, 작업 및 상태 테이블을 확인한다.
- DB 데이터와 설정의 백업 절차를 만든다.

### 4단계: 서비스 설정

- Vibe Coding API 서버 실행
- Telegram 봇 APIS 1·2·3 연결
- ITCP 송수신 연결
- Windows 작업 스케줄러 또는 서비스 방식으로 부팅 시 자동 실행
- 프로세스 비정상 종료 시 재시작 정책 적용

## 7. 검증 계획

### 기본 검증

- PostgreSQL 5433 접속 성공
- Vibe Coding 서버 상태 API 응답
- `pg_messages` 메시지 입력·조회 성공
- APIS 1·2·3이 Telegram 그룹에서 각각 응답
- Miix 재부팅 후 서비스 자동 복구

### 24시간 시험

- 1시간, 6시간, 12시간, 24시간에 상태 확인
- CPU와 메모리 사용률 확인
- C드라이브 증가량 확인
- 내부 팬 소음과 본체 온도 확인
- Telegram 응답 지연과 누락 확인
- 네트워크 재연결 후 자동 복구 확인

### 합격 기준

- 24시간 동안 서비스 비정상 종료 없음
- 재부팅 후 사람의 조작 없이 핵심 서비스 복구
- Telegram 세 봇의 송수신 성공
- C드라이브 여유 공간 25GB 이상 유지
- 지속적인 긁힘·진동성 팬 소음 없음

## 8. 장애 시 되돌리기

- 기존 PC의 서비스는 Miix 검증 완료 전까지 삭제하지 않는다.
- Miix 전환 중에는 기존 서버를 중지하되 설정과 DB 백업은 보존한다.
- Miix에서 장애가 발생하면 Telegram 봇 토큰과 DB 연결 대상을 기존 PC로 되돌린다.
- 최소 3일간 안정적으로 동작한 뒤 기존 환경 정리를 결정한다.
