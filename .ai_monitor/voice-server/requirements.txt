# 받아쓰기(STT)
faster-whisper==1.2.1

# 낭독(TTS) — 유일한 엔진. 마이크로소프트 Edge 읽어주기를 그대로 부른다.
# [WHY 이것만 남았나 — 2026-08-15 실측] 로컬 후보 6종이 전부 떨어졌다(Kokoro 는 한국어
#   목소리가 0개). 모델 0개·GPU 0·문장당 0.5~1.1초. 근거는 engines/tts_edge.py 헤더.
# [🔴 네트워크가 필요하다 — 되돌아갈 길은 여기 없다] 2026-08-15 정리로 sherpa-onnx(28MB)
#   와 pywin32(SAPI)를 걷어냈다. 망이 끊겼을 때 읽는 것은 **프론트의 브라우저 내장
#   합성기**(vibe-view/src/lib/browserVoice.ts)다 — 이 venv 밖이라 여기 적을 것이 없다.
#   무음이 되는 것이 이 스택에서 가장 나쁜 결과이므로, 그 경로를 지우지 말 것.
edge-tts==7.2.8

# 낭독(TTS) 두 번째 — 사장님 목소리 복제. engines/tts_qwen.py 가 쓴다.
# [WHY 들어왔나 — 2026-08-16 청취 판정] 사장님이 직접 들으시고 "그냥이 훨씬 좋은데. 굿.
#   교체 진행해보자" 로 채택. edge 를 대신하는 것이 아니라 하나 더 붙는 것이다.
# [🔴 이것을 깔면 GPU 를 문다] 모델 ~2.2GB 가 상주해야 문장당 지연이 산다. 같은 카드에서
#   학습이 돌면 그만큼 학습 몫이 준다. 그래서 tts_qwen 이 여유 VRAM 을 재고 1GB 밑이면
#   안 올린다. 아예 끄려면 VOICE_QWEN=0.
# [🔴 torch 는 CUDA 판이어야 한다] 기본 pypi 의 torch 는 +cpu 라 이 엔진이 못 뜬다.
#   CPU 로는 문장당 수 분이라 낭독으로 쓸 수 없다. 설치 예:
#     uv pip install torch --index-url https://download.pytorch.org/whl/cu130
# [🔴 실측] 예열 뒤에도 문장당 12.7~17.2초(RTF 5.9~6.7)다. 그때그때 읽기에는 못 쓰고,
#   정해진 문구를 미리 구워 cache/tts 에 넣어 두는 쓰임이 본래 자리다.
qwen-tts==0.1.1
