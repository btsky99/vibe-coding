# 규칙 9 — 프롬프트 컨텍스트 상한

## 상한표

| 종류 | 키 | 상한 | 대상 |
|------|-----|------|------|
| 재정박 프롬프트 | `reanchor` | 1500자 | 리사이클 후 새 세션에 주입하는 첫 프롬프트 |
| 워커 브리프 | `brief` | 1200자 | 에이전트 간 위임 지시 |
| 체크포인트 의도 | `intent` | 200자 | `active_session_context.intent` |
| 체크포인트 다음단계 | `next_step` | 200자 | `active_session_context.next_step` |

정본은 `src/brief_limits.py`의 `LIMITS` dict다. **표를 고치면 양쪽을 같이 고친다** —
어긋나면 이 문서가 거짓말을 한다.

## 왜 '줄'이 아니라 '글자'인가

규칙 2(파일당 1500줄)는 **코드 파일**용이다. 프롬프트에는 그대로 쓸 수 없다.

- 프롬프트는 개행이 거의 없어 줄 수가 크기의 프록시로 무의미하다
- 한글은 토큰당 글자 수가 영어보다 작아 char가 토큰 추정에 더 가깝다

## 왜 상한이 필요한가

리사이클(Phase 6)의 목적은 컨텍스트 회수다. 그런데 마지막 단계인 재정박 프롬프트가
뚱뚱하면 새 세션이 태어나자마자 컨텍스트를 다시 채운다 — **자기모순**이다.
상한은 리사이클이 실효를 갖게 만드는 전제조건이다.

## 중간 절단 (`truncate_smart`)

상한 초과 시 **뒤가 아니라 중간**을 자른다.

```
[앞 60%] …(N자 생략)… [뒤 40%]
```

일반적인 tail 절단(`text[:limit]`)을 쓰면 재정박 프롬프트의 "다음 할 일"이 통째로
날아가 리사이클의 목적 자체가 파괴된다. 앞(목표·의도)과 뒤(다음 할 일)는 둘 다
필수이고, 버릴 수 있는 건 중간(경과 서술)뿐이다.

앞을 6:4로 더 남기는 이유 — 목표 진술이 다음 단계보다 재구성 비용이 크다.

## 위반 시 동작 — 차단이 아니라 축약

```python
text, info = enforce('reanchor', raw)   # 예외를 던지지 않는다
if info['truncated']:
    ...  # 판단은 호출부 몫
```

**차단하면 안 되는 이유**: REANCHOR가 실패하면 세션을 되살리지 못한다. 이는
`docs/DISCORD_HARNESS_INTEGRATION_PLAN.md`의 보안 불변식 10
("체크포인트 저장 실패 시 현재 세션을 파괴하지 않는다")과 정면 충돌한다.
상한은 품질 장치이지 안전 장치가 아니다 — 안전이 우선한다.

## 재정박에 규칙 '본문'을 넣지 말 것

새 세션은 CLAUDE.md와 `.claude/rules/`를 자동 로드한다. 재정박 프롬프트에는
**경로만** 적는다. 본문을 복사하면 같은 내용을 두 번 먹여 컨텍스트를 낭비한다.
