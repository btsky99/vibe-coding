# 음성 — 기대 동작 (사장 지시, 2026-08-18)

> 이 문서는 **코드만 봐서는 알 수 없는 것**이다. 여기 안 적으면 다음 사람이
> edge 폴백을 "폴백이니 정상"으로 읽는다. 실제로 그렇게 읽혀서 며칠을 잃었다.

---

## 1. 기기마다 나야 하는 목소리가 다르다

| 어디서 | 나야 하는 목소리 | 코드 이름 |
|---|---|---|
| 모바일 | edge 목소리 | `edge:ko-KR-*` |
| 사장님 PC | **사장님 본인 목소리로 설정해 둔 것** | `qwen:apix` (또는 `moss:apix`) |

사장 말씀 원문(2026-08-18): "소리가 모바일에서는 엣지 목소리로 나오는 게 맞고.
내 PC에서는 내 사장 목소리 Q&A로 설정한 거로 나오는 게 맞아."
— 말씀의 **"Q&A" 는 엔진 이름 Qwen** 이다. 코드에서는 `qwen:apix`.

**저장 위치는 기기별이다** — `vibe.voice.id` (localStorage, `vibe-view/src/lib/voiceBus.ts:153`).
그래서 "모바일은 edge / 내 PC 는 내 목소리"가 서버 설정 하나로 갈리지 않는다.
서버 쪽 기본값은 `qwen:apix` (`voice-server/voice_server.py:409`).

## 2. 🔴 edge 로 떨어지는 것은 **정상이 아니다**

사장님 PC 에서 `qwen:apix`/`moss:apix` 를 골랐는데 edge 소리가 나면 **위반이다.**
"어쨌든 소리는 났으니 됐다"로 읽지 마라 — 사장님이 원한 것은 소리가 아니라 **본인 목소리**다.

**판정법 (2026-08-18 실측으로 확립):**

- `moss:apix` 를 요청했는데 **edge 와 바이트까지 같은 mp3(13,536B)** 가 오면 조용한 폴백이다.
  고친 뒤에는 384,044B wav 로 바뀐다 — 크기가 다르면 다른 엔진이 답한 것이다.
- `/api/voice/status` 응답에 **`ref` 키가 없으면** 참조 목소리(사장님 원본 wav)가 안 걸린 것이다.
  이 상태로도 합성은 되지만 **남의 목소리가 난다.** 정상일 때는 이렇게 나온다:
  `"ref": {"key": "boss_pick", "file": "…/ref/boss_pick.wav", "sha256": "…", "sec": 11.99}`
- 목소리 목록에 `moss:apix` 가 없으면 **낡은 동봉 사이드카**가 돌고 있는 것이다
  (`api/voice_api.py` `_app_src_root` 주석 참조).

## 3. 그래서 무엇을 확인해야 하는가

낭독을 고쳤다고 말하기 전에 **소리가 났는가**가 아니라 **누구 목소리인가**를 확인한다.
귀로 판정하지 말 것 — 위 세 가지는 전부 기계로 잴 수 있다.

    curl -s http://127.0.0.1:<앱포트>/api/voice/status   # ref 키 · moss 존재 확인
    # moss 와 edge 를 각각 합성해 바이트 수를 견준다 — 같으면 폴백이다
