# 위키 작성 규약 (wiki/)

> 이 프로젝트의 지식 창고는 `wiki/` 다. **사람도 LLM 도 읽는 백과사전**이며,
> 로그가 아니다. 페이지를 쓰기 전에 이 문서를 읽는다.

---

## 0. 3층 — 무엇이 정본인가

```
① wiki/*.md      정본. 사람이 고치고 git 이 버전 관리한다
② zettel_notes   인덱스. ①에서 생성되며 언제든 버리고 다시 만들 수 있다
③ 옵시디언        선택적 뷰어. 없어도 ①②로 완전히 동작해야 한다
```

**②를 직접 고치지 말 것.** DB 를 고치면 다음 인덱싱에서 덮어써진다.
고칠 대상은 언제나 ① 파일이다.

**③에 의존하지 말 것.** 옵시디언 전용 문법(`![[embed]]`, Dataview 쿼리 등)을 쓰면
설치 안 된 PC 에서 페이지가 깨져 보인다. `[[위키링크]]` 는 허용 — 없으면 그냥 텍스트로 읽힌다.

## 1. 절대 규칙 3개

### 규칙 1 — 추가가 아니라 덮어쓰기

새 사실을 알게 되면 **새 페이지를 만들지 말고 해당 페이지를 고친다.**

이것이 제텔카스텐과 갈리는 지점이다. 2026-08-15 이전 창고가 3969장까지 부푼 이유가
"계속 추가"였고, 그중 활성은 501장·실제 회상된 것은 극소수였다. 반면 같은 기간
`memory/` 98장은 **덮어쓰기 규약** 하나로 100% 활용됐다.

> 새 페이지를 만들기 전에 자문한다: **이 내용을 담을 페이지가 이미 있는가?**
> 있으면 그 페이지를 고친다. 애매하면 고치는 쪽을 택한다.

### 규칙 2 — 150장 상한

전체 페이지 수가 150 을 넘으면 **합치거나 버린다.**

백과사전은 커지는 게 아니라 정확해지는 것이다. 상한이 없으면 규칙 1이 무너진다 —
"한 장 더" 가 항상 합치는 것보다 쉽기 때문이다. `scripts/wiki_lint.py` 가 초과를 경고한다.

### 규칙 3 — 모든 주장에 출처

주장 옆에 `파일:줄번호` 또는 커밋 해시를 박는다. 출처를 못 대는 주장은 **쓰지 않는다.**

```markdown
데몬은 이름 없는 daemon 스레드에서 돈다 — `infra/daemons.py:983`
CREATE_NO_WINDOW 는 자식에 상속되지 않는다 — 사고 2건(d423a7d, 2026-08-14)
```

[WHY] 출처 없는 문장은 시간이 지나면 **검증 불가능한 전설**이 된다. 코드가 바뀌어도
아무도 그 문장이 틀렸다는 걸 모른다. 출처가 있으면 `wiki_lint.py` 가 기계적으로 검사한다.

## 2. 무엇을 쓰고 무엇을 쓰지 않는가

| 쓴다 ✅ | 쓰지 않는다 ❌ |
|---|---|
| 왜 이 방식을 골랐나 (버린 대안 포함) | 코드를 읽으면 아는 것 |
| 불변식·제약 (락 순서, 호출 컨텍스트) | 파일 역할 나열 (헤더에 이미 있음) |
| 과거 사고와 그 원인 | 커밋 제목 (git 에 이미 있음) |
| 외부 의존의 함정 | **세션 요약·대화 기록** |
| 실측 수치와 그 재현법 | **세션 캐시(`hive_memory`)** |

🔴 **세션 캐시와 세션 요약은 위키에 넣지 않는다.** 백과사전과 작업기억은 층이 다르다.
그 경계를 안 지킨 결과가 "지식 창고인 줄 알았던 로그 덤프" 였다(2026-08-15 실측:
활성 노트의 다수가 세션요약이었고 어떤 질문에도 걸려 회상 블록을 채웠다).

기준은 CLAUDE.md 규칙 3(LLM 관점 주석)과 같다 — **코드만 봐서는 알 수 없는 것만.**

## 3. 디렉토리

```
wiki/
├─ INDEX.md      목차. 사람에겐 지도, LLM 에겐 라우팅 표. 페이지 추가 시 함께 갱신
├─ 개념/         이 프로젝트가 어떻게 굴러가나 (아키텍처·원리·용어)
├─ 시스템/       서브시스템별 (회상·데몬·PTY·릴리즈·음성…)
├─ 함정/         과거 사고·제약. 같은 실수를 두 번 하지 않기 위한 층
└─ 결정/         왜 이렇게 했나. 버린 대안과 그 이유
```

**파일명**: 한글 제목을 그대로 쓴다(`회상 파이프라인.md`). 검색·링크가 사람 말과
일치해야 옵시디언에서도 LLM 에게도 편하다. 공백 허용, 특수문자(`/\:*?"<>|`) 금지.

```markdown

title: 회상 파이프라인
type: 시스템                  # 개념 | 시스템 | 함정 | 결정

  - .ai_monitor/src/pg_vector_search.py:258
  - e8fec8d
related:                      # 관련 페이지. [[링크]]로도 본문에 걸 것
  - 임베딩 모델 교체
  - 지식 창고 구조
confidence: high              # high | medium | low
updated: 2026-08-15
---

# 회상 파이프라인

## 한 줄

질의를 임베딩해 pgvector 로 유사 지식을 찾아 세션 시작 시 주입한다.

## 어떻게 도나

(구조. 코드를 그대로 옮기지 말고 **왜 그 구조인지**를 쓴다)

## 🔴 함정

- 보정항(참조·시간) 합은 관련/무관 유사도 간격보다 작아야 한다. 계수 0.1 이던 시절
  참조 82회 항목이 +0.442 를 받아 유사도 1위를 밀어냈다 — `pg_vector_search.py:262`, e8fec8d

## 확인법

(주장이 아직 맞는지 **재현하는 방법**. 이게 있어야 페이지가 늙지 않는다)

    python scripts/recall_quality.py --sweep
```

**`## 한 줄`은 필수.** LLM 이 회상에서 이 페이지를 만났을 때 첫 문장만 읽고 열지 말지
결정한다. 인덱서도 이 줄을 요약으로 쓴다.

**`## 확인법`을 되도록 넣는다.** 주장이 늙었는지 사람이 5초 안에 판정할 수 있게 한다.

## 5. 자주 하는 실수

- ❌ 페이지를 새로 만들고 기존 페이지를 방치 → 같은 주제가 두 장으로 갈라져 둘 다 신뢰를 잃는다
- ❌ 출처 없이 "~하는 것으로 보인다" → 검증 불가능한 전설이 된다
- ❌ 코드 블록을 통째로 복사 → 코드가 바뀌면 즉시 거짓말이 된다. 경로:줄번호로 가리킬 것
- ❌ 세션에서 있었던 일을 서술 → 그건 로그다. 남는 건 "그래서 무엇이 참인가" 뿐이다
- ❌ DB(`zettel_notes`)를 직접 수정 → 다음 인덱싱에 덮어써진다

## 6. 관련 도구

| 명령 | 하는 일 |
|---|---|
| `python scripts/wiki_build.py` | 원료(주석·사고·메모리) → 위키 페이지 생성 |
| `python scripts/wiki_lint.py` | 죽은 출처·고아 페이지·상한 초과 검사 |
| `python scripts/recall_quality.py --sweep` | 회상 품질(관련/무관 간격) 재측정 |
| `POST /api/wiki/reset` | 위키 전체 초기화 후 원료에서 재생성 (설치본 포함) |
