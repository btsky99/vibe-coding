# 파일 크기 제한 + LLM 관점 주석

## 규칙 2 — 파일당 1500줄 제한 (주석 포함)

### 강제 기준
- **상한**: 주석 포함 `wc -l <file>` ≤ 1500
- **권장 분할 시점**: 1200줄 도달 시 미리 분할 검토
- **자동 생성 파일은 제외**: `dist/`, 마이그레이션 SQL, 번들 결과물

### 왜 1500줄인가
- LLM 컨텍스트 효율: 한 파일을 통째로 읽어도 ~50KB 이하 → 토큰 부담 없음
- 사람 인지: 한 파일을 머리에 담을 수 있는 한계
- 책임 단일성: 한 파일에 두 도메인 이상이 섞이면 보통 1000줄을 넘김
- 머지 충돌 감소: 작은 파일일수록 동시 편집 충돌이 줄어듦

### 분할 판단 기준 (어떻게 나눌지)
1. **도메인 경계로**: 같은 외부 시스템과 통신하는 함수끼리 묶는다 (예: `tasks_api.py`, `git_api.py`)
2. **추상화 레벨로**: 상위 오케스트레이터 vs 하위 유틸리티 분리
3. **변경 빈도로**: 자주 바뀌는 핸들러 vs 안정적인 상수/스키마 분리
4. **순환 의존 금지**: 분할 후 `import` 그래프에 사이클이 생기면 인터페이스 재설계

### 분할 절차
1. 새 파일 생성 (표준 헤더 포함)
2. 함수 그룹을 잘라 이동
3. 원본 파일에서 `from <new_module> import ...`로 재노출 (호환성 필요 시만)
4. `PROJECT_MAP.md` 줄 수 갱신
5. 커밋: `refactor(<scope>): 파일 분할 — <원본> → <신규>`

### 현재 위반 파일 (점진 분할 대상)
- `.ai_monitor/server.py` (5103줄) — 분할 계획 진행 중 (`project_server_split_plan.md`)
- 신규 파일은 처음부터 1500줄 이하로 설계

## 규칙 3 — LLM 관점 주석

### 핵심 원칙
**주석의 독자는 사람이 아니라 다음 세션의 LLM이다.**

LLM은 코드를 읽으면:
- 변수 흐름, 호출 그래프, 타입을 즉시 파악한다
- 그래서 "X를 Y로 변환" 같은 자연어 풀어쓰기는 토큰 낭비다

LLM이 코드만 봐서 **모르는 것**만 주석에 적는다:
1. **WHY (의도)** — 왜 이 방식인가, 어떤 대안을 버렸나
2. **제약 조건** — 호출 컨텍스트, 동시성 가정, 플랫폼 의존성
3. **불변식** — 락 순서, 큐 producer/consumer 수, 상태 머신 단계
4. **과거 사고** — 이 코드가 막아낸 버그/이슈 (재발 방지)
5. **외부 의존 함정** — 라이브러리 정적 분석이 못 잡는 동적 import 등
6. **호환성 가정** — 이 함수를 누가/어디서 호출하는지 (개발/EXE/CI 모드별)

### ❌ 금지 — 사람용 주석 안티패턴

```python
# 사용자 정보를 가져온다
user = get_user(user_id)

# 결과를 반환
return result

# for 루프로 항목 처리
for item in items:
    process(item)

# 변수 초기화
counter = 0
```

이런 주석은 코드를 그대로 자연어로 옮긴 것 — **제거 대상**.

### ✅ 필수 — LLM용 좋은 주석 예시

```python
# [WHY] DB 락이 아닌 파일 락 사용 — psycopg3가 advisory_lock에서 timeout을 못 잡아
# 무한 대기 사고(v3.7.142) 발생. 파일 락은 OS 레벨에서 즉시 타임아웃 됨.
with file_lock(LOCK_PATH, timeout=5):
    ...

# [제약] 이 함수는 단일 스레드 전제 — 내부 cache는 lock 보호 없음.
# 멀티스레드 호출 필요하면 caller가 직접 RLock 잡아야 함.
def get_cached_config():
    ...

# [불변식] release_a → release_b 순서 고정. 역순 시 v3.7.198에서 데드락 사고.
def cleanup():
    release_a()
    release_b()

# [과거사고] v3.7.215~218: spec datas 갱신 시 CI --add-data도 동시 갱신해야 함.
# 한쪽만 바꾸면 로컬 통과/CI 설치 EXE 누락. 체크리스트: vibe-coding.spec ↔ build-release.yml
hiddenimports = ['urllib.request']

# [PyInstaller 함정] 정적 분석이 stdlib 동적 import를 놓침 →
# 명시 안 하면 frozen 모드에서 ImportError. 추가 시 spec/CI 양쪽 동기.
```

### 주석 작성 체크리스트
새 주석을 쓰기 전 자문한다:
- [ ] 이 정보가 코드 본문에 이미 있는가? → 있으면 주석 삭제
- [ ] LLM이 다음 세션에서 이 주석을 읽고 더 빠르게 일할 수 있는가? → 아니면 삭제
- [ ] WHY/제약/불변식/과거 사고/외부 함정 중 하나에 해당하는가? → 해당하면 유지
- [ ] 향후 동작이 바뀌면 이 주석도 함께 갱신될 수 있는가? → 갱신 가능한 곳에만 작성

### 표준 헤더는 예외 — 항상 유지
파일 최상단의 `FILE/DESCRIPTION/REVISION HISTORY` 블록은 **LLM이 파일을 열기 전 검색용**이라
"사람용 자연어 풀어쓰기"가 아니다 — 그대로 유지.
