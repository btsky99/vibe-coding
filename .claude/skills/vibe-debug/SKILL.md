# 디버깅 — Subagent 위임 래퍼

## 0단계 (필수): 사고 장부 조회 — Agent 호출 전에

```bash
python scripts/incident.py search "<에러 메시지 핵심 부분>"
```

- **과거 동일/유사 사고 히트 시**: 기록된 근본원인/수정법을 먼저 검토. 동일 사고면
  subagent 위임 없이 그 수정법을 바로 제안한다 (재분석 = 삽질).
- 히트 없음 → 아래 Agent 위임 진행.

당신은 **즉시 Agent 도구를 호출**합니다. 메인에서 스택 트레이스를 직접 분석하지 않습니다.

## 호출 사양

```
Agent(
  subagent_type: "debugger",
  description: "버그 근본 원인 분석 (4단계)",
  prompt: """
    작업 디렉토리: <호출 시점의 cwd — pwd로 확인. 절대 경로 하드코딩 금지>
    증상: <에러 메시지 전문 + 스택 트레이스 + 재현 조건 전달>
    사용자 요청 원문: <전달>

    출력: 한국어
    절차: 4단계 분석 프로토콜
      1단계: 증상 수집 (에러 전문 + git log -10 + 재현 조건)
      2단계: 가설 수립 (원인 후보 3개 이상, 가능성 높은 순)
      3단계: 검증 (최소 재현 코드 + 가설별 확인/반박)
      4단계: 근본 원인 확정 + 수정 방안 제안

    **중요 — 수정 권한 가드 (세분화):**
    - 허용: 진단용 임시 로그/print 추가 (3단계 검증 목적, 이후 제거)
    - 금지: 비즈니스 로직 수정 + 수정 커밋 + 파일 영구 변경
    - 4단계 "수정"은 **수정 방안 제안**이며, 실제 적용은 사용자 승인 후 메인 에이전트가 수행한다.
    - 임시 진단 로그라도 보고 시 "이 줄은 진단 목적으로 추가했으며 제거 필요" 명시.

    결과 형식:
      🔍 근본 원인 (Why): 1줄
      📍 위치: 파일:줄
      💡 수정 방안 (How): 1~2줄, 최소 변경
      🧪 검증 가설: 어떤 가설을 통과해 결론에 도달했는지
  """
)
```

## Subagent 결과 수신 후 (메인 보고 형식)

1. **근본 원인 1줄** (subagent의 Why 그대로)
2. **위치 + 수정 방안** (파일:줄 + 1~2줄)
3. **"이대로 수정할까?"** 대기 — 사용자 승인 시 메인이 Edit 도구로 직접 수정

## 수정 완료 후 (필수): 사고 장부 기록

수정이 적용되고 검증이 끝나면 **반드시** 장부에 기록한다 — 이걸 빼먹으면
다음에 같은 에러가 와도 회상이 안 된다 (자가 치유 루프의 쓰기 절반):

```bash
python scripts/incident.py record --error "<에러 원문>" --cause "<근본 원인 1줄>" --fix "<수정법 1줄>" --commit "<커밋 해시>" --files "<수정 파일들>"
```

"⚠️ 재발 사고" 경고가 뜨면 이전 수정이 근본 원인을 못 잡았다는 뜻 —
이번 수정이 왜 다른지 사용자에게 명시 보고한다.
